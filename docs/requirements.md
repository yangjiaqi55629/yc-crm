## 2. 业务背景与问题

元川 AI 门户网站当前通过弹窗表单收集潜在客户的姓名、手机号和邮箱。表单提交后，数据写入门户自身 SQLite 数据库中的 `leads` 表；门户后台只能查看、刷新和删除线索，无法支持系统化的客户维护与销售跟进。

当前存在的主要问题如下：

1. 留资数据与后续客户管理混在门户系统中，无法形成独立、连续的客户档案。
2. 同一客户多次留资时，现有系统会形成多条线索，无法识别重复客户。
3. 没有结构化跟进记录，无法回顾沟通内容、判断客户意向或安排下一次联系。
4. 没有待办和逾期提醒，容易遗漏应联系的客户。
5. 没有基于客户资料和沟通历史的销售辅助能力。

因此，需要建设一个独立、轻量、单人可高效使用的 CRM：门户负责获取线索，CRM 负责客户沉淀、跟进、提醒和销售辅助。

## 3. 产品愿景、目标与成功标准

### 3.1 产品愿景

让每一条门户留资都成为可持续经营的客户关系：看得到、跟得上、不重复、不遗漏，并能获得可执行的销售建议。

### 3.2 本期产品目标

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| G-01 | 留资不丢失 | 门户提交成功的客户信息可同步进入 CRM，并可追踪同步异常。 |
| G-02 | 客户不重复 | 按手机号将同一客户的多次门户留资合并为一个客户档案。 |
| G-03 | 跟进可追溯 | 每次沟通、状态变化和下一次计划均沉淀到客户时间线。 |
| G-04 | 待办可执行 | 用户进入 CRM 即可识别今日待跟进和已逾期客户。 |
| G-05 | 销售有辅助 | 用户可针对单个客户主动生成画像和下一步销售建议。 |

### 3.3 建议验收指标（待评审）

| 指标 | 推荐基线 | 说明 |
| --- | --- | --- |
| 同步时效 | 正常情况下 60 秒内 | 从门户留资成功到 CRM 出现客户或留资事件。 |
| 同步完整性 | 不允许静默丢失 | 同步失败必须可重试、可查看。 |
| 重复控制 | 同手机号不新增客户 | 多次留资仅增加时间线记录。 |
| 待办准确性 | 与下次跟进时间一致 | 到期和逾期客户应在工作台正确出现。 |

## 4. 用户、角色与使用场景

### 4.1 用户角色

本期仅存在一个账号角色：**CRM 管理员/销售**。该用户拥有全部客户数据的查看、编辑、跟进、归档和 AI 分析权限。

本期不建设多账号、团队、客户分配、数据隔离或角色权限管理。

### 4.2 核心使用场景

| 场景 | 用户目标 | 系统应提供的支持 |
| --- | --- | --- |
| 门户产生留资 | 不漏掉新线索 | 实时创建或更新 CRM 客户，并记录来源。 |
| 开始一天工作 | 确定优先联系谁 | 工作台展示今日应跟进、逾期、高意向和新增客户。 |
| 联系客户后 | 记录进展并安排下一步 | 新增结构化跟进记录与下次跟进时间。 |
| 客户再次留资 | 避免重复建档 | 自动匹配已有手机号并追加事件。 |
| 不清楚如何推进 | 获得沟通思路 | 生成客户画像、沟通重点、问题和话术建议。 |
| 主动收录客户 | 补录线下或其他来源客户 | 手动新建客户，并标识为手动录入。 |

## 5. 产品范围

### 5.1 本期范围（In Scope）

1. 单账号登录。
2. CRM 工作台与客户待办。
3. 门户留资实时同步。
4. 客户档案的新建、查看、编辑、搜索、筛选与归档。
5. 基于手机号的客户去重与合并。
6. 客户状态、来源、标签、需求信息维护。
7. 跟进记录及客户全量时间线。
8. CRM 内到期和逾期提醒。
9. AI 客户画像与销售建议。
10. 同步失败记录与重试保障。

### 5.2 非本期范围（Out of Scope）

| 功能 | 本期处理方式 |
| --- | --- |
| 多人销售协作、分配、权限 | 不建设 |
| 订单、合同、回款、发票 | 不建设 |
| 短信、邮件、企业微信等外部提醒 | 不建设，仅 CRM 内提醒 |
| 批量 Excel 导入导出 | 不建设 |
| 市场活动、营销自动化 | 不建设 |
| 自动向客户发送 AI 内容 | 不建设，AI 仅提供建议 |
| 门户历史测试数据迁移 | 不迁移；当前 3 条测试留资排除 |

### 7.4 客户去重与门户同步

#### 7.4.1 同步原则

门户网站为客户留资来源，CRM 为后续客户经营系统。门户留资成功后必须触发向 CRM 的实时同步。

#### 7.4.2 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-SYNC-001 | 手机号是客户自动匹配的唯一依据。 |
| BR-SYNC-002 | CRM 中不存在该手机号时，创建一名新客户，来源为“门户网站”，状态为“待跟进”。 |
| BR-SYNC-003 | CRM 中已存在该手机号时，不创建第二名客户；追加一条“门户再次留资”时间线事件。 |
| BR-SYNC-004 | 重复留资不得覆盖用户在 CRM 中手动维护的公司、需求、标签、状态和跟进信息。 |
| BR-SYNC-005 | 门户同步的姓名、邮箱如与 CRM 已有值不同，系统应在时间线保留本次原始数据，具体自动更新策略见待评审项。 |
| BR-SYNC-006 | 同步失败不得静默丢失；必须记录失败状态、失败原因和重试次数。 |
| BR-SYNC-007 | 同一门户留资事件重复推送时，CRM 必须具备幂等处理能力，不得重复生成时间线事件。 |

#### 7.4.3 功能明细

| 编号 | 需求 | 优先级 | 验收说明 |
| --- | --- | --- | --- |
| FR-SYNC-001 | CRM 提供供门户调用的留资接收能力。 | P0 | 门户可提交姓名、手机号、邮箱、来源、留资时间及唯一事件标识。 |
| FR-SYNC-002 | 接收成功后自动创建或合并客户。 | P0 | 符合上述去重规则。 |
| FR-SYNC-003 | 客户详情页显示门户留资历史。 | P0 | 可区分首次留资与再次留资，显示原始姓名、手机号、邮箱和时间。 |
| FR-SYNC-004 | 提供同步异常查看能力。 | P0 | 可查看失败事件、原因、状态和最近重试时间。 |
| FR-SYNC-005 | 支持对失败同步进行自动重试与人工重试。 | P0 | 失败恢复后不重复创建客户或事件。 |

### 7.5 客户状态与标签

#### 7.5.1 状态定义

| 状态 | 定义 | 使用说明 |
| --- | --- | --- |
| 待跟进 | 新留资或暂未开始处理 | 新门户客户默认进入此状态。 |
| 跟进中 | 已联系，正在持续沟通 | 常规销售推进状态。 |
| 高意向 | 需求明确、优先级较高 | 应优先安排后续跟进。 |
| 已转化 | 已达成本业务的预期结果 | 本期仅标记结果，不生成订单。 |
| 无效/流失 | 信息无效、明确无需求或长期无响应 | 可在未来重新激活。 |

#### 7.5.2 规则

- 用户可在客户详情页手动修改客户状态。
- 客户从“已转化”或“无效/流失”状态重新产生业务机会时，允许重新设为“待跟进”“跟进中”或“高意向”。
- 状态变更必须进入客户时间线。
- 标签为辅助分类，不替代客户状态；一名客户可拥有多个标签。

### 7.7 CRM 内提醒与待办

#### 7.7.1 提醒规则

| 编号 | 规则 |
| --- | --- |
| BR-REM-001 | 客户设置下次跟进时间后，进入 CRM 待办队列。 |
| BR-REM-002 | 下次跟进日期为当天的客户，归入“今日应跟进”。 |
| BR-REM-003 | 下次跟进时间早于当前时间，且尚未完成后续跟进的客户，归入“已逾期”。 |

- 本期仅在 CRM 工作台、客户列表和客户详情中展示提醒。
- 本期不发送短信、邮件、微信、浏览器推送或其他外部通知。

### 7.8 AI 客户画像与销售建议

#### 7.8.1 使用方式

用户在客户详情页主动发起分析。系统不自动触发分析、不自动修改数据、不自动对外发送消息。

#### 7.8.2 AI 输入

- 客户基本资料：姓名、联系方式、公司、职位、行业、地区。
- 需求信息：需求描述、预算范围、标签、客户状态。
- 门户留资历史。
- 跟进记录与历史沟通内容。

用户已确认：允许将上述客户资料和跟进内容发送至后续选定的 AI 模型服务进行分析。

#### 7.8.3 AI 输出

| 输出项 | 说明 |
| --- | --- |
| 客户画像摘要 | 对客户背景和当前情况的概括。 |
| 需求与关注点 | 识别客户明确或潜在的需求。 |
| 意向判断 | 对当前意向程度的建议性判断及依据。 |
| 沟通重点 | 下一次沟通应优先确认的重点。 |
| 建议问题 | 可向客户追问的问题。 |
| 下一步行动 | 推荐的跟进动作与节奏。 |
| 沟通话术 | 可复制、可编辑的首轮或后续沟通文本。 |

#### 7.8.4 功能明细

| 编号 | 需求 | 优先级 | 验收说明 |
| --- | --- | --- | --- |
| FR-AI-001 | 客户详情页提供“生成 AI 分析”入口。 | P0 | 用户可手动发起分析。 |
| FR-AI-002 | 系统展示结构化画像与销售建议。 | P0 | 输出包含本节定义的核心内容。 |
| FR-AI-003 | AI 输出支持复制使用。 | P0 | 用户可复制话术或建议文本。 |
| FR-AI-004 | AI 不得自动修改客户状态、资料或跟进记录。 | P0 | 所有修改必须由用户明确保存。 |
| FR-AI-005 | AI 结果应保留生成时间与所依据的客户历史范围。 | P1 | 用户可判断建议是否过期。 |

| 客户 | CRM 中唯一的客户主档 | 客户编号、姓名、手机号、邮箱、状态、来源、标签、需求、跟进时间。 |
| 留资事件 | 保存每一次门户留资原始记录 | 门户事件标识、客户、姓名、手机号、邮箱、来源、提交时间、同步状态。 |
| 跟进记录 | 保存每次人工跟进 | 客户、沟通方式、跟进时间、内容、结果、下次跟进时间。 |
| 客户时间线事件 | 统一展示客户生命周期 | 客户创建、门户留资、资料修改、状态变更、跟进、AI 生成。 |
| 标签 | 客户辅助分类 | 标签名称、关联客户。 |
| AI 分析记录 | 保存 AI 输出与生成上下文 | 客户、生成时间、输入范围、画像、建议、模型信息。 |
| 同步任务/异常 | 确保门户到 CRM 的可靠同步 | 门户事件标识、状态、失败原因、重试次数、最后重试时间。 |

## 9. 非功能需求

### 9.1 数据与可靠性

| 编号 | 需求 |
| --- | --- |
| NFR-001 | 客户、跟进和同步事件的创建与更新必须记录创建/更新时间。 |
| NFR-002 | 同一门户事件重复发送时，系统不得生成重复客户或重复留资事件。 |
| NFR-003 | 同步失败必须可见、可追踪、可重试。 |
| NFR-004 | 归档客户及其历史时间线、跟进记录不可因常规操作丢失。 |
| NFR-005 | 系统应具备数据备份与恢复方案，具体频率待技术设计确定。 |

### 9.2 安全与隐私

| 编号 | 需求 |
| --- | --- |
| NFR-SEC-001 | CRM 业务数据必须在登录后访问。 |
| NFR-SEC-002 | 登录密码不得以明文方式长期保存。 |
| NFR-SEC-003 | 门户向 CRM 推送数据时必须具备调用身份校验机制，避免公开接口被伪造调用。 |
| NFR-SEC-004 | 手机号、邮箱、跟进内容属于客户敏感信息，不应在未登录页面、日志或错误提示中完整暴露。 |
| NFR-SEC-005 | 调用 AI 服务时，应避免在前端暴露 AI 服务密钥。 |

### 9.3 易用性

| 编号 | 需求 |
| --- | --- |
| NFR-UX-001 | 工作台应在一次进入后展示当天待办，无需额外筛选操作。 |
| NFR-UX-002 | 新增一条常规跟进应可在客户详情页完成，不应跳转多个页面。 |
| NFR-UX-003 | 客户列表、详情、待办中的状态名称和日期规则应保持一致。 |
| NFR-UX-004 | 所有时间展示使用北京时间（GMT+8）。 |

## 10. 待评审与待决策事项

以下事项影响后续技术方案或细节规则，需在需求评审中明确：

| 编号 | 待决策事项 | 推荐方案 | 影响范围 |
| --- | --- | --- |
| D-01 | CRM 部署位置与访问域名 | 与门户可安全互通的独立部署地址 | 门户同步、登录、运维 |
| D-02 | 门户调用 CRM 的认证方式 | 使用服务端密钥或签名校验，不使用公开无鉴权接口 | 数据安全、接口设计 |
| D-03 | 资料冲突处理 | 重复留资不覆盖 CRM 人工维护内容；原始新值进入时间线并提示用户查看 | 去重、客户资料 |
| D-04 | 客户归档规则 | 默认软归档，可恢复；不提供普通用户永久删除 | 数据保留、列表展示 |
| D-05 | “已转化”定义 | 由用户手动标记，不要求订单或合同数据 | 客户状态、统计 |
| D-06 | AI 服务商与模型 | 评审后选择，密钥由服务端保管 | AI 功能、成本、安全 |
| D-07 | AI 分析结果保存周期 | 建议保留历史分析版本，便于比较客户变化 | 数据存储、客户详情 |
| D-08 | 同步时效正式 SLA | 建议以“正常情况下 60 秒内”作为首期验收标准 | 接口、监控、验收 |
| D-09 | 未来数据导出 | 本期不做，后续按实际经营需要评估 | 版本规划 |

## 11. 验收测试场景

| 编号 | 前置条件 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| AT-01 | CRM 无该手机号客户 | 门户提交一条新手机号留资 | CRM 创建一名“待跟进”客户，并生成门户留资事件。 |
| AT-02 | CRM 已有该手机号客户 | 门户再次提交相同手机号 | CRM 不新增客户，仅增加一条再次留资事件。 |
| AT-03 | 存在待跟进客户 | 用户新增电话跟进并设置明天的下次跟进时间 | 跟进进入时间线，客户出现在明日待办。 |
| AT-04 | 存在下次跟进时间早于当前时间的客户 | 进入工作台 | 该客户出现在已逾期清单。 |
| AT-05 | 客户状态为无效/流失 | 用户重新设为高意向 | 状态更新成功，时间线记录状态变更。 |
| AT-06 | 门户向 CRM 推送失败 | 系统自动或人工重试 | 恢复后只生成一次正确的客户或留资事件。 |
| AT-07 | 客户存在基础资料与跟进记录 | 用户点击生成 AI 分析 | 系统展示画像、建议问题、下一步动作和可复制话术。 |
| AT-08 | AI 分析完成 | 用户未执行任何保存操作 | 客户状态、资料和跟进记录不会被 AI 自动改写。 |
| AT-09 | 存在 3 条门户测试线索 | CRM 初始化或首轮同步 | 该 3 条测试线索不进入 CRM。 |
